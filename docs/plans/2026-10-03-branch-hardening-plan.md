# 分支完善计划（2026-10-03）

**状态：已完成**（验证结果见文末）。

分支 `feature/context-aware-correction`。问题来源：用户反馈三点 + 后端/前端代码审计 + 真实运行（隔离 HOME 的后端、模拟与真实 DeepSeek 接口、浏览器驱动真实前端）。

## 已确认的问题

- **布局**：结果区最挤（1024 宽时结果栏约 280px，导出按钮被挤出），中间导入栏大片留白。
- **按钮失灵**：全部停止/移除停不住批处理且行状态卡在"进行中"；批处理中切标签页丢进度；"已保存"提示永不出现；批处理中移除文件仍被转写且状态标错行。
- **纠错慢**：DeepSeek `reasoning_effort=low` 每批 1000 字 14–17s（思考 2000+ token），非流式；关闭思考 + 流式：首字 2.9s、约 400 字/s，5 处错误同样改对 4 处。
- **进度/状态**：纠错与转写进度互相覆盖（进度倒退、纠错面板闪烁）；乱序批次清空 result_text；任务失败/暂停后被迟到回调改回 RUNNING；删除任务后排队批次仍全部发出计费；纠错全失败无提示。
- **时间码**：未用 SenseVoice 逐字时间戳，按字数平分最长 30s 的 VAD 段；VAD 段贴边截断丢句尾字（实测"什么样的爱"→"什么样的？"）；"？。"双标点；SRT 用原文却标 corrected。
- **其他**：settings.json 并发非原子写（可丢 API Key）；英文纠错拼接缺空格；含 `/` 的热词删不掉；未用依赖 modelscope / huggingface_hub / llama-cpp-python；构建时仍下载 2GB 旧纠错模型。

## 用户决定

1. 布局：结果优先两栏。左栏 = 新建按钮 + 任务库；主区 = 选中任务时原文/纠错左右对照（全高），否则导入页；整窗可拖入文件。
2. Markdown 替代 JSON：`# 文件名` + 分段正文，不带时间码。
3. 开启纠错时 SRT 用纠错后文字，按字对齐回原文逐字时间戳。

## 验证结果

- 后端 pytest 76 项、前端 vitest 35 项全部通过（连跑 30 次 / 10 次无偶发失败）；ruff / black / isort、eslint、tsc、前端 build 均通过。
- 字幕时间码：用宣传片旁白（TTS 逐词时间即真值）对照，字幕起点平均偏差 0.05 s，最大 0.19 s。
- 句尾丢字：原先"什么样的爱"被截成"什么样的？"，修复后完整。
- 流式纠错（模拟接口，7 分钟音频）：4.6 s 出现第一段纠错文字，纠错文本只增不减、总进度不回退；取消后不再发出请求。
- 真实 DeepSeek（42 s 讲道）：转写 1.3 s，纠错 4.0 s 出字、4.6 s 完成（改造前同一段纠错耗时 12.4 s，且完成前不出字）。
- 浏览器驱动真实前端：两栏布局在 1280 / 1024 宽、中英文下无溢出；批处理中切换视图不丢进度；Esc 关闭设置。
- 未验证：本机无 Rust 工具链，Tauri 权限配置的编译期校验交给 GitHub 构建流程。
